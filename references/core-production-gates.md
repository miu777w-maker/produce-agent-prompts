# 七项核心生产门禁

## 使用方式

在架构设计前完整执行七项门禁。每项同时回答：生产前需要什么信息、形成什么显式产物、产生什么对正式文件的约束、什么情况阻塞生成、生成后如何复查。使用 `pass`、`warning`、`fail`、`blocked`；任一关键项为 `fail` 时停止生成。

### 闭环要求（防止形式通过）

七项门禁是闭环，不是填表：

- 每项**显式产物必须含对正式文件的具体约束**（“这对最终 prompt 文件的命名/拆分/职责/内容意味着什么”），不只是分析记录。
- 交付前必须把七项约束与**最终文件清单和正文反向核对**。
- 填写了表格或章节不等于通过；缺少运行时代码、schema 或真实装配证据时，只能标记“设计假设/待核验”，不得写成已验证 `pass`。
- 任一核心门禁未满足，不得把任务标记为完成或静态通过。

### 运行时证据缺失分级

- **阻断生成（业务语义层）**：目标、角色、职责、门禁判定标准等业务语义层契约缺失，且知识库无法补全 → 停止生成，输出补全请求。
- **仅标 warning（工程实现细节）**：工具 schema 精确字段、注入钩子代码、数据结构实现细节等，不影响 prompt 文本语义 → 标“设计假设/待代码核验”，不阻塞生成，但该门禁不得写 `pass`。

## 1. 需求先行与范围推导

### 生产前获取

- 原始要求、目标、系统范围和不可改变要求；
- 交付范围与明确排除项；
- prompt 清单来源：人员给定清单 / 目标驱动发现；
- 目标驱动时，从目标、执行单元、规则作用域推导候选清单的入口。

### 显式产物与约束

形成目标与范围确认、清单来源判断。约束：确定后续清单推导方式（验证人员清单 vs 目标驱动发现）和文件边界判断的起点；明确哪些执行单元在范围内、哪些排除。

### 失败条件

目标或范围未明确且无法从知识库推导；不可改变要求与知识库事实冲突且未裁定；把现有文件列表误当作应有清单。

### 生成后复查

最终 prompt 清单是否覆盖全部目标执行单元；是否有越出范围或遗漏关键执行单元；清单来源是否被忠实保留（人员清单未被静默改写）。

## 2. Agent 运行环境

### 生产前获取

- Agent/模型调用节点与触发条件；
- 可见的 system/developer/user/tool 等消息及装配顺序；
- 动态变量、状态、历史和知识注入；
- 工具名称、schema、调用条件和结果消费者；
- 输出格式、parser、下游用途和异常路径；
- reminder/anchor 注入钩子；
- prompt/schema/code/eval 版本关系。

### 显式产物与约束

形成 Agent 运行环境说明及逐 prompt 的运行时集成契约。约束：每个 prompt 单元的工具、消息角色、装配顺序、异常路径必须与契约一致；动态变量不得写死进静态 prompt。

### 失败条件

关键消息、状态、工具、输出、异常或版本需要猜测；prompt 声称可用的能力在运行时不可确认（业务语义层缺失且 KB 无法补全 → 阻断）。

### 生成后复查

逐项核对 prompt 的占位符、工具、输出和错误处理是否与契约一致。缺少代码实现证据时只能标记“契约已设计/待代码核验”，不能标记“可接入已验证”。

## 3. 关键执行时机上下文与概念绑定

### 生产前获取

为每个关键模型调用时机列出实际上下文快照：消息角色、顺序、静态 prompts、动态状态、历史范围、工具 schema 和上游输出。

### 显式产物与约束

形成：

1. 执行时机上下文契约；
2. 概念引用绑定表，记录 prompt 中的术语/代词、明确含义、注入来源、可见时机、缺失行为。

约束：prompt 中每个术语/代词必须在目标执行时机有真实可见的注入来源；“计划注入”不等于“运行时真实可见”。

### 失败条件

消息组成或注入不明；“上述规则”“事件要素”“当前状态”等引用在当前上下文没有明确绑定；上游只传值但下游依赖未传入的定义。

### 生成后复查

扫描所有指代、术语、字段和上下文依赖，并在真实装配快照中定位其定义。无法定位的关键引用一票否决。

## 4. 业务与角色行为

### 生产前获取

- 产品/业务目标和服务对象；
- Agent 身份、专业定位和要完成的业务结果；
- 明确不做什么、目标优先级和安全边界；
- 语气、表达对象和沟通要求；
- 领域术语和必要定义；
- 信息不足、拒绝、冲突、越界和异常时的行为；
- 来源及其版本/适用范围限定。

### 显式产物与约束

形成业务与角色行为契约。约束：角色规则必须分配到真实可见的 prompt 层；身份、目标、边界、异常行为必须忠实表达，不得擅自添加知识库没有的身份或承诺。

### 失败条件

身份来自非最终材料且未裁定；只有语气形容词而无可执行边界；目标、服务范围和拒绝范围冲突；角色规则没有分配到真实可见的 prompt 层。

### 生成后复查

检查 prompt 是否忠实表达目标、行为边界和异常行为，是否擅自添加知识库没有的身份或承诺。

## 5. prompt 职责与信息可见性

### 生产前获取

还原所有执行单元、prompt/动态上下文/工具载体、上下游关系和每条规则的作用域。

### 显式产物与约束

形成矩阵：载体、唯一主要职责、必须知道、可以知道、不应知道、上游、下游、规则来源。约束：职责矩阵必须**反向约束实际架构**——共享底座不得吞并局部任务细节，局部 Agent 不得读取无关执行单元规则；门禁 Agent 不应被注入与其职责无关的回复业务规则。

### 失败条件

职责重叠或遗漏；无理由重复；局部逻辑泄漏给无关 Agent；task 实际不继承其依赖规则；reminder 复制整份主 prompt；动态状态被写死。

### 生成后复查

检查每条关键规则是否有一个主要责任载体；重复是否因新执行时机或自包含确有必要；局部任务是否只读取最小充分范围。

## 6. 关键约束与注意力安排

### 生产前获取

为每条关键约束记录业务/安全影响、适用执行单元、主要归属、易失效时机、漂移原因和可用运行时钩子。

### 显式产物与约束

形成关键约束清单及注意力方案：结构位置、标题、必要重注入、reminder/anchor、工具强制、schema 或程序门禁，并说明注入方、时机、重复理由和测试方式。约束：不是所有重要规则都需要 anchor；确定性约束优先使用 code/schema；anchor 必须有真实钩子和必要性，不能只是形式设计。

### 失败条件

关键规则埋在长文中；声称存在的 anchor 钩子未确认；anchor 与 task 冲突；anchor 承载大量新逻辑；没有针对漂移场景的 eval。

### 生成后复查

验证每个 reminder/anchor 的必要性和运行时真实性。

## 7. 知识疑点与冲突

### 生产前获取

检查当前任务涉及知识的定义、流程、职责、工具、字段、引用、版本、显式限定，以及 prompt 与 eval 各自的来源与版本状态。

### 显式产物与约束

形成报告：疑点、相关来源、可疑原因、影响范围、是否关键、建议补充方、解决后回退阶段。未发现时也写明“已检查，未发现影响本次任务的明显知识问题”。约束：发现的冲突、非最终内容或断链必须按来源和责任方处理，不得静默带入正式文件。

### 失败条件

存在影响当前 prompt 的明显错误、冲突、断链或非最终内容且未解决。

### 生成后复查

检查 prompt 是否误读来源、丢失适用范围、引入无来源规则或在知识更新后发生漂移。

## 总门禁顺序

按以下顺序推进：

`目标与任务流程 → 需求先行与范围推导 → 知识就绪 → 七项核心门禁 → prompt 清单与架构确认（含文件边界与命名） → 逐单元生成`

不要因局部非关键警告阻塞无关产物；也不要用“后续再补”绕过关键失败。七项门禁的约束必须在交付前与最终文件反向核对。
