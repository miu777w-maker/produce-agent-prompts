# 六项核心生产门禁

## 使用方式

在架构设计前完整执行六项门禁。每项同时回答：生产前需要什么信息、形成什么显式产物、什么情况阻塞生成、生成后如何复查。使用 `pass`、`warning`、`fail`；任一关键项为 `fail` 时停止生成。

## 1. Agent 运行环境

### 生产前获取

- Agent/模型调用节点与触发条件；
- 可见的 system/developer/user/tool 等消息及装配顺序；
- 动态变量、状态、历史和知识注入；
- 工具名称、schema、调用条件和结果消费者；
- 输出格式、parser、下游用途和异常路径；
- reminder/anchor 注入钩子；
- prompt/schema/code/eval 版本关系。

### 显式产物

形成 Agent 运行环境说明及逐 prompt 的运行时集成契约。

### 失败条件

关键消息、状态、工具、输出、异常或版本需要猜测；prompt 声称可用的能力在运行时不可确认。

### 生成后复查

逐项核对 prompt 的占位符、工具、输出和错误处理是否与契约一致。缺少代码实现证据时只能标记“契约已设计/待代码核验”，不能标记“可接入已验证”。

## 2. 关键执行时机上下文与概念绑定

### 生产前获取

为每个关键模型调用时机列出实际上下文快照：消息角色、顺序、静态 prompts、动态状态、历史范围、工具 schema 和上游输出。

### 显式产物

形成：

1. 执行时机上下文契约；
2. 概念引用绑定表，记录 prompt 中的术语/代词、明确含义、注入来源、可见时机、缺失行为。

### 失败条件

消息组成或注入不明；“上述规则”“事件要素”“当前状态”等引用在当前上下文没有明确绑定；上游只传值但下游依赖未传入的定义。

### 生成后复查

扫描所有指代、术语、字段和上下文依赖，并在真实装配快照中定位其定义。无法定位的关键引用一票否决。

## 3. 业务与角色行为

### 生产前获取

- 产品/业务目标和服务对象；
- Agent 身份、专业定位和要完成的业务结果；
- 明确不做什么、目标优先级和安全边界；
- 语气、表达对象和沟通要求；
- 领域术语和必要定义；
- 信息不足、拒绝、冲突、越界和异常时的行为；
- 来源及其版本/适用范围限定。

### 显式产物

形成业务与角色行为契约。

### 失败条件

身份来自非最终材料；只有语气形容词而无可执行边界；目标、服务范围和拒绝范围冲突；角色规则没有分配到真实可见的 prompt 层。

### 生成后复查

检查 prompt 是否忠实表达目标、行为边界和异常行为，是否擅自添加知识库没有的身份或承诺。

## 4. prompt 职责与信息可见性

### 生产前获取

还原所有执行单元、prompt/动态上下文/工具载体、上下游关系和每条规则的作用域。

### 显式产物

形成矩阵：载体、唯一主要职责、必须知道、可以知道、不应知道、上游、下游、规则来源。

### 失败条件

职责重叠或遗漏；无理由重复；局部逻辑泄漏给无关 Agent；task 实际不继承其依赖规则；reminder 复制整份主 prompt；动态状态被写死。

### 生成后复查

检查每条关键规则是否有一个主要责任载体；重复是否因新执行时机或自包含确有必要；局部任务是否只读取最小充分范围。

## 5. 关键约束与注意力安排

### 生产前获取

为每条关键约束记录业务/安全影响、适用执行单元、主要归属、易失效时机、漂移原因和可用运行时钩子。

### 显式产物

形成关键约束清单及注意力方案：结构位置、标题、必要重注入、reminder/anchor、工具强制、schema 或程序门禁，并说明注入方、时机、重复理由和测试方式。

### 失败条件

关键规则埋在长文中；声称存在的 anchor 钩子未确认；anchor 与 task 冲突；anchor 承载大量新逻辑；没有针对漂移场景的 eval。

### 生成后复查

验证每个 reminder/anchor 的必要性和运行时真实性。不是所有重要规则都需要 anchor；确定性约束优先使用 code/schema。

## 6. 知识疑点与冲突

### 生产前获取

检查当前任务涉及知识的定义、流程、职责、工具、字段、引用、版本、显式限定和 prompts/evals 同步状态。

### 显式产物

形成报告：疑点、相关来源、可疑原因、影响范围、是否关键、建议补充方、解决后回退阶段。未发现时也写明“已检查，未发现影响本次任务的明显知识问题”。

### 失败条件

存在影响当前 prompt 的明显错误、冲突、断链或非最终内容且未解决。

### 生成后复查

检查 prompt 是否误读来源、丢失适用范围、引入无来源规则或在知识更新后发生漂移。

## 总门禁顺序

按以下顺序推进：

`目标与任务流程 → 知识就绪 → 六项核心门禁 → prompt 清单与架构确认 → 逐单元生成`

不要因局部非关键警告阻塞无关产物；也不要用“后续再补”绕过关键失败。
