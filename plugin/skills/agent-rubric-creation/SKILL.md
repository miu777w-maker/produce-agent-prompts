# Agent Rubric Creation

生成评价完整 Agent 实际表现的 **Rubric(评分细则)**。**不生成 Eval 测试场景、用户输入、环境状态、测试数据或评测执行方法**。

## Rubric 是什么

- 评价完整 Agent 实际表现(可观察行为和结果)的评分细则,**不是**系统 Prompt 文本的写作质量;
- 形式上可为人工评判者或 Judge Agent 的评价提示词;
- 条目必须**可验证、可打分**(明确评分标度)、尽量**正交**(避免同一错误被重复评价);
- 评分维度按任务选择(事实准确、完成结果、指令遵循与步骤边界、工具/权限边界、语气得体、简洁度等),**不机械全含**。

## 事实基础(不用七项写作检查)

本 skill **不机械执行"Prompt 七项写作检查"**——不评价"Prompt 是否写清运行环境"这类写作质量。
但评分条目须以 **Agent 事实**为依据:七项对应信息(`${CLAUDE_PLUGIN_ROOT}/shared/core-principles.md`)仅作为**事实完整性检查**(需求范围、运行环境、上下文、业务角色、职责与可见性、关键约束、知识疑点),**只读取与当前评分对象有关的事实,不要求每项都形成 Rubric 条目**;事实内容一律**从知识库检索**取得。缺少事实依据的条目会要求 Agent 完成其做不到的事,或漏掉越权、上下文不足等严重问题。

## 本任务工具与授权

只读知识库、可写 Rubric;不访问后端、不写知识库、不修改 Prompt。**默认禁止读取 Prompt 文件**(即使仓库内有也不主动读);除非用户**明确强力要求**,才在授权下读取,且**知识库仍为唯一知识源**——不以 Prompt 复制/降低/缩窄评分,Prompt 与 KB 冲突时依 KB 并标记冲突而非迁就。涉及外部访问 / 子 Agent 时读 `${CLAUDE_PLUGIN_ROOT}/shared/tool-permissions.md` 共同清单。

## 主流程(Rubric 侧)

1. **明确评测对象与范围**——被评 Agent、可观察行为、评判者(人工 / Judge Agent)、评分用途。
2. **从知识库检索与评分对象有关的事实**——运行环境、上下文、角色/目标/语气/行为边界、职责、关键约束、知识疑点等(七项对应信息作完整性检查,只取相关的,不要求逐项都用)。**默认不读 Prompt 文件**(例外同权限行)。
3. **按任务选择评分维度**——从"常用评分维度参考"按任务挑,不机械全含。
4. **逐条目编写**——条目可观察(基于消息/工具调用/输出等证据)、可打分(明确标度)、正交(条目归属唯一维度,处理维度间重叠);可设一票否决(仅破坏正确性/安全/运行契约的严重错误);与 Prompt 理解不同时依 KB,标记冲突而非迁就。
5. **倒查交付**——每条目是否可验证/可打分;评价依据是否完整(七项对应信息作事实完整性检查);是否忠于 KB、无 Eval 测试体系外溢;产物命名/拆分是否服从 KB 规范。

## 常用评分维度参考

| 维度 | 评什么 |
| --- | --- |
| 事实准确 | 事实性内容(数字/日期/引用/名称)与 KB 是否一致 |
| 完成结果 | 是否达成任务目标、产出是否完整可用 |
| 指令遵循与步骤边界 | 是否按要求的流程/步骤执行、是否越过步骤边界 |
| 工具或权限边界 | 是否调用授权工具、是否越权(该做未做 / 不该做却做) |
| 语气得体 | 表达是否符合角色语气与场合 |
| 简洁度 | 是否冗长、重复、夹带无关信息 |

按任务选用,不机械全含;条目层须正交化,避免同一错误被多个维度重复处罚。

## Prompt 与 Rubric 的关系

二者可在同一项目阶段**同步形成**;各自**从知识库独立推导**。Rubric **不以已生成的 Prompt 为知识来源或正确答案**;Prompt **不决定** Rubric 的数量、评分维度或文件结构。产物正式文件名、目录、拆分方式服从知识库已有规范,本 skill 不自行命名、合并或拆分。

## Rubric 修订入口

本 skill 承担"新建或修订 Rubric"。Prompt Revision 发现变更影响 Rubric 时,只记录 Rubric 重新评估需求并交回本 skill,不在 Prompt Revision 中直接修改(除非用户另行启动并授权)。
