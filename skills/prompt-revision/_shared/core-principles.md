# 共同核心原则(七项宪法)

> 本文件是七项原则的**唯一权威定义**。所有任务 skill 启动时读“七项宪法”(本文件开头,很短)。
>
> **“职责与信息可见性”原则也反向约束 Skill 自身**:Skill 也不加载当前任务用不到的流程、规则、知识和文件。删掉任意一条 Skill 规则,若不影响“写前找对范围 / 写时约束正式产物 / 写完发现错误并停止”,即可精简。

## 七项宪法(启动读)

1. **需求先行与范围推导**——目标、范围、不可改变要求、清单来源是否明确,是否从知识库正确推导。
2. **Agent 运行环境**——工具、消息、状态、输出消费者、异常路径是否真实可见。
3. **关键时机上下文与概念绑定**——术语/代词/概念在该执行时机是否有真实可见的输入与定义。
4. **业务与角色行为**——角色身份、服务对象、目标、语气、行为边界、业务约束。
5. **职责与信息可见性**——每部分唯一职责、去重、渐进式披露、最小可见信息。**本项反约束 Skill 自身**(见上)。
6. **关键约束与注意力安排**——重要易漂移要求的有效位置;anchor/reminder 必须有运行时钩子和必要性。
7. **知识疑点与冲突**——明显错误、冲突、断链、版本问题或非最终内容,按来源和责任方处理。

七项是闭环:每项必须**逐项分析并约束正式产物**(分析 → 对正式文件的具体约束 → 交付前倒查)。只记录阻断、缺失、冲突和必要的追溯结论,**不强制每项生成独立过程文件**。任一未满足,不得声称完成或通过。即使未发现疑点也显式记录结论。

## 工具与授权

各任务的特定权限写在各自 SKILL.md 的“本任务工具与授权”行(自包含)。**启动只读七项 + 本任务权限行**;仅当涉及外部访问 / 子 Agent / 权限疑点时,才读 `_shared/tool-permissions.md` 共同协议。本文件不重复工具授权定义。
