# Runtime Integration Validation

**双环境定位**:知识库环境验证“应该怎样”(由 Creation/Inspection/Revision 负责);本 skill 在**后端仓库环境**验证“实际怎样”。两环境互不替代、互不静默覆盖。

## 本任务工具与授权
只读知识库 / Prompt;后端仓库仅四条件授权后只读;项目代码只读核验不修改;不写知识库。**默认只读、只报告;不静默选边 KB 或代码**(差异先归因)。本任务涉及后端访问,启动读 `_shared/tool-permissions.md` 外部访问四条件;涉及子 Agent 时读其子 Agent 规则。

## 只读边界(不顺便做)
不改 Prompt、不改代码、不改 KB、不决定产品应迁就代码、不重审全部业务知识(角色/业务/语气/产品决策归 Inspection 与人员)。

## 核验范围(只核验 KB 中可与实现对应的部分)
文件名、装配位置、工具 schema/参数/枚举/返回、消息、字段、输出消费、异常路径、加载时机、跨层冲突。**不重新判断**角色定位/业务策略/语气/产品决策。

## 主流程
1. **确认授权**:用户主动要求 + 提供后端仓库地址 + 说明目的范围 + 仅授权范围定向只读(四条件齐备才进入)。
2. **建立对照**:读取带元信息的 Prompt 生产稿(预期契约)+ KB 依据;按授权范围读后端代码/Schema/装配/钩子。
3. **逐项对照**:元信息预期 vs 代码事实(装配顺序/每 Agent 实收消息/动态注入/工具契约/输出消费/异常/文件名 vs 配置/跨层冲突)。
4. **差异归因(四类,不静默选边)**:Prompt 误写 / KB 过时 / 后端偏差 / 无法判断。代码证"当前实际值";KB 证"预期设计";修哪边由人员裁定。
5. **产出报告**:预期 vs 实际对照表 + 差异归因 + 上线阻断项 + KB 补充请求(转人员)+ 工程修改请求(转人员)+ Prompt 问题(转 Prompt Revision)。**据上线阻断项是否清零,报告标注“有阻断(未通过)”或“无阻断(可定稿)”**(见“报告标注”);阻断项转交后回验前不得标“无阻断”。

## 本流程七项映射(对照后端版)

| 七项 | Runtime Validation 检查什么 |
| --- | --- |
| 需求先行 | 用户授权的仓库、目的、范围、被核验的生产稿 |
| 运行环境 | 真实消息装配顺序、工具 schema/参数/枚举/返回、输出消费、异常路径 |
| 上下文绑定 | Prompt 预期概念与真实注入消息/字段的对应 |
| 业务背景 | 仅核对代码是否承载已确认业务要求,不重新决定业务知识 |
| 职责与渐进披露 | 每个 Agent 实收信息是否符合预期职责;共享底座是否泄漏无关规则 |
| 关键约束位置 | anchor/reminder 是否真有运行时钩子、加载时机是否如声明 |
| 知识错误 | KB 预期与代码事实差异归因(四类),不静默选边 |

## 报告标注(完成 ≠ 通过)

对照完成、产出报告后,**报告须标注是否有未解决上线阻断项**:

- **有阻断**(未通过、不可定稿):阻断转交 Prompt Revision / 工程 / KB,回验前不升通过;
- **无阻断**(可定稿):元信息仍在,转交人员定稿。

“对照完成 + 报告产出”是**完成**不是**通过**;只有“无阻断”才可定稿。`final-runtime-prompt`(人员手动删元信息后的运行稿)**不由本任务产生**——本任务不删元信息、不改产物。
