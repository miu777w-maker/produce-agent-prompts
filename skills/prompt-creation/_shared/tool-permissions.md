# 工具使用与授权协议(共同清单)

> 本文件是**所有任务共用的工具授权权威**:概念边界 + 共同禁止清单 + 外部访问四条件 + 子 Agent 规则。
> **各任务的特定权限(读 / 写哪些)写在各自 SKILL.md 的"本任务工具与授权"行**(自包含,不集中在本文件)。
> 任务启动读本任务 SKILL 的权限行即可;涉及**外部访问 / 子 Agent / 权限疑点**时再读本文件。

## 概念边界:三层能力(必须区分)

- **逻辑授权**:Skill 规定本任务能不能做某事。本协议约束这一层。
- **技术能力**:宿主实际向 Agent 提供哪些工具(如文件系统读取、子 Agent 调用)。
- **技术限制**:沙箱或权限系统是否真正阻止。

Skill 规定**逻辑授权**;**工具本身由宿主提供,技术权限由运行环境强制**。本协议不冒充系统级权限控制。若宿主给的能力超出逻辑授权,Agent 仍须遵守不越界;若宿主支持权限隔离,应同步配置技术权限。

## 外部仓库访问四条件

任意任务访问**非当前项目知识库**的外部仓库(后端 / 前端 / 其他项目)时,四条件必须齐备:

1. 用户**主动、明确**要求进行该项核查;
2. 用户**提供具体仓库地址**;
3. 用户**说明访问目的与范围**;
4. Skill 只在**授权范围内定向只读**。

每次外部访问记录:仓库、目的、范围、只读确认。

## 知识库缺运行时信息时

不自行访问后端。标记缺失 → 说明影响的 Prompt / 规则 / 结论 → 生成可由人员转交后端 / 前端 Agent 的信息请求 → 不把对话临时答复当作 KB 已更新 → 正式依据须由人员补入 KB 后重新检索。

## 共同禁止清单(即使工具可用也不允许)

- 不擅自访问未授权仓库 / 目录(即便技术上可读);
- 不把对话中的临时答复当作 KB 已更新;
- 不自动删除 Prompt 元信息;
- 不静默选择 KB 或代码任一方(差异先归因);
- 不自动跨流程修改 Eval(Prompt Revision 尤其);
- 不自行修改后端代码(Runtime Integration Validation 只报告);
- 不默认扫描全库、不默认读取范围外 Eval;
- 不用任务级职责声明"对冲 / 抵消"system 与 task 的冲突或 system 信息污染(冲突须修架构 / 装配)。

## 子 Agent 调用规则

- **默认禁止**直接联系其他项目 Agent 取得正式知识(应由人员转交信息请求)。
- **例外(用户明确授权且宿主支持范围继承时)**:可在当前授权任务内调用受控子 Agent 协助**只读**检查。
  - 子 Agent **继承相同仓库、范围和只读限制**;
  - 子 Agent 的发现仍属本次任务证据,**不自动写回知识库**;
  - 不绕过人员直接向后端项目 Agent 取正式知识。
