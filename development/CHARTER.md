# 最高指令(CHARTER)

> 本仓库的稳定章程:目的、各 skill 用途、最高原则、核心边界、审查判据。**几乎不修改**。
> 运行层方法见 `shared/` 与 `skills/`;此处只放最高层。
> 日期:2026-08-13(v0.4)。

## 一、目的

produce-agent-prompts 是**为写 Agent 提示词而生的 skill 仓库**。从一个项目知识库出发,产出**可追溯、可接入运行时、可评测**的 Agent prompt + eval + rubric。仓库的产物是 **Skill 本身**(供 Claude / Codex 加载执行),不是某个业务的 prompt。

## 二、各 skill 用途

| skill | 用途 | 状态 |
| --- | --- | --- |
| `produce-agent-prompts` | 指挥官:任务路由,不重复各任务方法 | 可用 |
| `prompt-creation` | 新建 prompt 体系(不产 eval),从 KB 独立推导,七项生产原则 | 可试运行 |
| `agent-eval-creation` | 生成评测场景(完整 Agent 业务行为),从 KB 独立推导,**默认禁读 Prompt**,不机械套七项;需评分细则时条件调 rubric | 可试运行 |
| `agent-rubric-creation` | 生成 Rubric(评分细则),评价 Agent 实际表现的可观察行为与结果,从 KB 独立推导 | 可试运行 |
| `runtime-integration-validation` | 后端运行时校验(用户授权后端后),预期—实际对照,**只读只报告** | 原型 |
| `prompt-inspection` / `prompt-revision` | 检查 / 改写已有 prompt | **占位未实现**(触发返回未实现) |

## 三、最高原则:七项宪法(所有任务唯一宪法)

1. 需求先行与范围推导
2. Agent 运行环境(工具 / 消息 / 状态 / 输出 / 异常真实可见)
3. 关键时机上下文与概念绑定
4. 业务与角色行为
5. 职责与信息可见性(**本项反约束 Skill 自身**:不加载当前任务用不到的流程 / 规则 / 文件)
6. 关键约束与注意力安排(anchor 须有运行时钩子和必要性)
7. 知识疑点与冲突

七项约束正式产物,逐项分析 + 倒查;**不要求每项生成独立过程文件**;任一未满足不得声称完成。权威定义:`shared/core-principles.md`。

## 四、核心边界(几乎不改)

- **Prompt / Eval / Rubric 三条独立流程**,各自从 KB 独立推导;阶段同步 ≠ 生产绑定。
- **默认禁读 Prompt**:`agent-eval-creation` / `agent-rubric-creation` 默认不读 Prompt 文件(即使仓库内有),除非用户明确强力要求(此时 KB 仍唯一源)。
- **权限自包含**:各 skill 写全本任务权限;启动只读七项 + 本任务权限行;外部访问 / 子 Agent / 权限疑点才读共同协议(`shared/tool-permissions.md`)。
- **双环境**:KB 环境(应该怎样)vs 后端环境(实际怎样),互不替代 / 覆盖;差异归因,不静默选边。
- **元信息生命周期**:生产 / 审查 / 修订 / 后端校验期保留,人员定稿删,Skill 不擅删。
- **不碰真实项目**(Prompt / Eval / KB / 后端代码);不写死项目字段。
- **清单 / 协议已写入 ≠ 端到端已通过**;未经验证不写成既定事实。
- **不为未出现的问题预先加状态机 / 层 / 协议**;真实缺口补最小规则。
- **占位 skill 未实现**:触发返回"流程未实现",不用通用能力临时完成。

## 五、三层结构(几乎不改)

- **提示词层**:`shared/core-principles.md`(七项权威)。
- **执行策略层**:`skills/<task>/SKILL.md`(主流程 + 本任务权限行 + 七项映射)。
- **工具授权层**:`shared/tool-permissions.md`(共同清单)。

## 六、如何审查(skill 体系演进判据)

- **删减判据**:删某规则是否导致 ①范围错 ②内容错 ③越权访问 ④漏上线风险?都不会 → 删 / 降。**复杂性留验证体系,不进执行上下文。**
- **加东西前问**:这是真实缺口,还是"为保证正确而加结构"?后者叫停。
- **最小执行上下文**:指挥官 → 目标 task skill → core-principles + 本任务权限行;不应被迫载入其他任务的规则 / 状态 / 工具协议。
- **测试(`tests/`)只用于**:新版发布前 / 权限·职责·状态·知识来源规则变更后 / 真实执行暴露新型严重错误后;**不每次生产都跑**。
- **审查关注点**:七项编号 / 引用正确无残留;权限自包含且必要禁止内联;无虚假文件引用;占位 skill 防假可用;KB 依据 vs 后端实证不混。

## 七、发布边界(几乎不改)

- 不因一次结果宣称全部任务通过。
- 不把项目业务规则固化进通用 skill。
- 不把静态校验称为外部行为通过。
- 不在 Inspection 中自动进入 Revision。
- 不删除原始输入或用后续分析覆盖。
- 每次版本说明修改原因、验证证据、未覆盖范围。

## 八、同步

- `shared/` 是源;各 skill `_shared/` 由 `scripts/sync-shared.py` 同步(`check` 防漂移)。
- 安装副本 `~/.claude/skills/<each>/` 用 rsync 从仓库 `skills/` 同步(v0.4 多 skill)。
- commit 本地 Claude 可做;`git push origin main` 需用户 `!`(分类器拦)。
