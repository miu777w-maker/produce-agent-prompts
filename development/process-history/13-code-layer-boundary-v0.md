# 提示词生产 Skill 的代码层边界 V0

> 结论：Skill 运行在项目知识库中，默认不直接实现或修改项目代码；但必须设计并输出提示词与代码之间的运行时集成契约。

## 一、需要区分的三层

### 1. 提示词语义层（Skill 直接负责）

- Agent 角色、任务和目标；
- 业务规则、判定标准和行为边界；
- 流程、状态机和输出要求；
- reminder/anchor 的内容；
- prompts 与 evals 的逐字产物。

### 2. 运行时集成契约层（Skill 直接负责设计）

- 每个 prompt 文件如何被代码加载；
- 在什么执行节点加载；
- 以什么 message role 和顺序装配；
- 哪些变量、状态、历史和知识在何时注入；
- 变量名、类型、是否必填和缺失行为；
- 哪些工具及 schema 对模型可见；
- 模型输出采用自然语言、结构化结果还是工具调用；
- 输出由哪个下游组件解析；
- 超时、异常、拒绝和工具失败如何处理；
- reminder/anchor 的注入钩子和频率；
- prompt、schema 与评测使用哪个版本。

### 3. 项目代码实现层（默认交给后端/前端 Agent）

- 修改消息装配代码；
- 实现 prompt loader；
- 注册工具与 schema；
- 注入 memory、事件或页面状态；
- 编写输出 parser 和异常处理；
- 接入评测运行器或 CI；
- 修改前后端接口。

知识库 Skill 发现实现缺失时，生成明确的工程交接请求；实现结果带证据回写知识库后，再核对集成契约。

## 二、运行时集成契约的最小字段

对每个提示词单元记录：

| 字段 | 内容 |
|---|---|
| Prompt ID / 路径 | 可执行文件的唯一标识 |
| 执行单元 | Agent、节点或模型调用 |
| 触发条件 | 何时加载 |
| 消息 role | system/developer/user/tool 或项目定义类型 |
| 装配顺序 | 与其他 prompt、历史和状态的相对位置 |
| 动态变量 | 名称、类型、来源、必填性、示例 |
| 状态与历史 | 注入范围、截取规则、空值行为 |
| 工具 | 名称、schema、调用条件、结果消费者 |
| 输出契约 | 格式、字段、parser 和下游用途 |
| reminder/anchor | 注入钩子、频率、条件 |
| 异常路径 | 超时、调用失败、拒绝、解析失败 |
| 版本 | prompt/schema/code/eval 的对应版本 |
| 来源知识 | 相关知识卡 |

## 三、代码层硬门禁

以下任一情况发生，提示词不能标记为“可接入”：

- 只写了变量占位符，但没有定义由谁、何时、以什么类型注入；
- prompt 声称能调用工具，但代码未注册或 schema 不一致；
- prompt 要求结构化输出，但下游没有对应 parser 或字段契约；
- reminder/anchor 写好了，但没有真实注入钩子；
- prompt 依赖对话历史或状态，但代码实际未提供；
- 消息装配顺序不明确，无法判断规则优先级；
- 异常处理只写在 prompt 中，却与程序实际处理机制冲突；
- prompt、eval 和运行代码版本无法对应。

## 四、Skill 的代码相关输出

当生产任务完成时，除 prompts 与 evals 外，建议输出：

1. 运行时集成契约；
2. 前后端实现缺口清单；
3. 可直接交给代码侧 Agent 的实现请求；
4. 集成静态检查清单；
5. 外部行为评测交接包。

### 工程交接请求至少说明

- 要接入哪个 prompt；
- 目标执行节点；
- 消息装配与注入要求；
- 工具、状态和输出契约；
- 需要修改或核查的代码范围；
- 完成后应返回的文件、符号、schema、测试和版本证据。

## 五、Skill 自身可以包含的代码

正式 Skill 可以自带确定性校验脚本，用于检查：

- prompt 与 eval 文件是否一一对应；
- 来源卡路径是否存在；
- 必填产物是否齐全；
- 变量占位符是否在集成契约中登记；
- 工具名和 schema 引用是否一致；
- 阶段状态与交付清单是否完整。

这些脚本服务于生产稳定性，不等于替项目实现 Agent 运行代码。是否加入脚本，应在正式 Skill 结构设计时根据重复性和可靠性需求决定。

## 六、资金安全顾问案例

以第二门禁为例，语义 prompt 之外还需要明确：

- `gate/fund_safety` 和 reminder 分别以什么消息角色加载；
- “结合上下文”具体由代码注入哪些消息；
- reminder 在哪一个内部循环钩子注入；
- `report_out_of_scope` 是否每次都调用；
- verdict true/false 的语义；
- reason 字段何时必填；
- 工具结果如何被门禁结果列表消费；
- 工具异常如何变成 `GateExecutionError`；
- 对应 rubric 如何取得工具调用记录。

这些内容不全部属于 prompt 文案，却决定 prompt 能否真实工作，因此必须由 Skill 形成集成契约并交给后端 Agent 核实或实现。
