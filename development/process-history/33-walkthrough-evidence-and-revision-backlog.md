## 三、分级方案

### (一)🔴 必须新增/强化(本次新发现 Skill 缺陷)

1. **跨层指令冲突检查**:按真实加载顺序组合检查 `system → 历史与动态状态 → 用户输入 → 工具定义 → task → reminder → anchor`,不逐文件孤立。system/task 相互否定(如"不负责门禁" vs 要求执行门禁)→ **fail**。本轮 P0 实证。
2. **渐进披露检查真实消息装配**:不只看 Prompt 文本职责矩阵,看每个执行单元**运行时实际收到**的全部信息(system_mem 注入了什么、共享 system 是否泄漏无关规则、task 是否被迫抵消上层指令、局部 Agent 是否获最小信息)。职责矩阵与真实装配不一致 → **fail 或架构阻塞**。第二轮 P1 坐实:为 KV cache 整段注入门禁致回复规则泄漏,Prompt 文本层无法根治 → Skill 必须识别并标架构阻塞,不 silently 通过。
3. **Prompt 元信息生命周期**:四态 `production-draft → experiment-candidate → finalization-review → final-runtime-prompt`;生产期保留(生成/审查/修订/追溯),定稿期由**人员手动删**,Skill 不擅自删、不默认清理;如实标记"元信息会随正文进入模型上下文"(C6 实证无剥离器);元信息中职责声明与正文/装配冲突 → **fail**;删前确保追溯信息已在别处保留。
4. **七项闭环**:每项 `证据 → 设计约束 → 影响的正式文件或运行时组合 → 最终核对 → 状态`;不只填表;元信息可作承载但结论必须与正文/装配一致。
5. **运行时诚实状态**:严格区分 `KB 记载 / 设计假设 / 用户裁定 / 代码·Schema·日志已证 / 静态通过 / 真实行为验证`;缺真实装配、工具 Schema 或钩子证据 → 不得写运行时门禁 pass,不得称可用或 `final-ready`。
6. **运行时取证优先(第二轮核心教训)**:Prompt 的工具契约(参数名/值/Schema)、概念绑定载体(字段 vs 消息)、anchor/reminder 注入时机、**运行时实际加载的载体范围**——以运行时代码/Schema/日志为准;KB 是设计来源但可能过时(K1-K4 实证)。运行时证据不足时**强制取证**(产出工程取证请求),不继续生成标"待核验"。
7. **Prompt 不引入 KB 未授权措辞**:自加推演句(如"你不负责...")标记待核验,不进正文当 KB 事实;七项第 7 项"引入无来源规则"含此。

### (二)🟡 建议修改(吸收直接语义版优势)

- 门禁/任务 Prompt 正文显式声明职责边界(P3:唯一任务/不做其他任务/不生成用户回复/只走专属工具),不只放矩阵。
- 追问/约束范围精确化(服务达标,非泛泛"最影响理解")。

### (三)🟢 已正确——保留 + 加防回归场景

A 类全部(Prompt/Eval 分离、文件级清单、8 文件正确、不私自命名/合并/多造、不产 Eval/交接、定向检索、产物克制)。加入下文回归场景,精简时不得删。

### (四)⚪ 暂不修改

- C 类项目侧:P1 架构根治、KB 回写(K1-K4)、Langfuse 取证、后端载体范围——项目组/Skill 侧只负责"识别并标记"。
- E 类行为验证:独立 `agent-eval-creation`。
- F 类元信息删除:用户指示时。

## 四、必须加入的回归场景(用户第五节 16 条 + 第二轮补充)

1. KB 定义 8 文件时准确生成 8;2. 不私自命名/合并/多造;3. Prompt Creation 不产 Eval 与外部交接;4. **system 与 task 相互冲突必须 fail**;5. 执行单元看到无关规则触发渐进披露问题;6. **职责矩阵与真实消息装配不一致不能通过**;7. 无代码/Schema/日志时运行时真实性不判 pass;8. 生产阶段正确保留元信息;9. 未经授权不自动删元信息;10. 定稿前提示人员清理元信息;11. 实验时准确记录元信息是否进入模型上下文;12. **元信息职责声明与正文/装配冲突必须 fail**;13. 无明确消费者的过程文件不生成;14. 局部任务不默认扫全库;15. Eval 独立从 KB 与完整 Agent 目标推导,不形成 Prompt→Eval 一一对应;16. Revision 不因 Prompt 变化自动跨流程改 Eval。
