## 一、任务目标

共同形成一个可复用 Skill，用于规范“一个系统中的 Agent 提示词体系”如何获取前置信息、完成设计与编写，并接受可追溯的校验。

资金安全顾问项目用于验证该 Skill，但不是 Skill 唯一适用的业务。

### 持续约束

- `00-original-task-input.md` 是本任务的最高层指导与最终验收基线。
- 后续方案必须能追溯到原始输入、用户明确修正或双方显式确认的判断。
- 无法追溯的新设计只能标记为候选方案，不能被静默写成既定需求。

## 二、从原始输入直接推导出的职责边界

### 1. 工作对象是“系统级提示词体系”

依据：原始输入同时讨论 MainAgent、门禁判断、Anchor、事件七要素、消息注入和渐进式披露。这些内容涉及多个执行时机和提示词层，不是单条 prompt 的润色问题。

因此 Skill 的工作对象至少包括：

- 系统中有哪些 Agent、任务节点或提示词层；
- 每一部分在何时执行；
- 每次执行时实际可见的消息、工具、状态和业务知识；
- 信息应放在哪一层，哪些层不应看到；
- 各提示词之间的引用和协作关系。

### 2. Skill 不能只提供静态检查清单

依据：任务要求“规范提示词的生产过程”，并特别补充“为了生成提示词需要哪些内容，以及如何获取这些内容”。

因此 Skill 至少要负责：

- 识别生产所需输入；
- 指导查找、索取和核验输入；
- 在信息不足时暂停不可靠的编写；
- 组织系统级职责和上下文分配；
- 生成或指导生成提示词产物；
- 校验产物是否满足原始要求。

### 3. Skill 必须区分通用方法与项目事实

通用方法进入 Skill 的核心流程；资金安全顾问的 MainAgent、三层门禁、Anchor、事件七要素及具体工具只用于案例验证。

## 三、原始注意事项的初步分类

### A. 生产前需要获取的事实

- Agent 运行环境；
- 可用工具及工具契约；
- 可能收到的系统消息、用户消息和其他上下文；
- 业务背景、角色身份、语气和行为边界；
- 任务约束与业务知识来源。

### B. 系统级设计工作

- 还原关键执行时机的真实上下文；
- 明确各提示词部分的作用和职责；
- 分配信息的可见范围；
- 消除重复、缺失、越权和无法解析的引用；
- 决定需要在哪些关键位置设置 reminder、anchor 或其他注意力机制。

### C. 生产后的校验

- 上下文中引用的概念是否真实存在且对应明确；
- 工具、消息、状态和知识是否与实际运行环境一致；
- 是否存在可疑知识错误；
- 是否违反职责边界和渐进式披露原则；
- 是否遗漏关键任务约束。

## 四、后续主线

## 七、已确认判断

### 判断 1：Skill 的工作对象与责任终点

- 工作对象：一个系统中的整套 Agent 提示词体系，而非单条 prompt。
- 责任终点：不能只输出建议或检查报告；至少需要形成信息来源与缺口记录、系统提示词架构及职责分配、具体提示词产物、校验结果与未决风险。
- 状态：用户已确认该判断符合原始任务。

### 判断 2：目标先行，按交付范围收集最小充分上下文

- 初始判断：先识别系统中实际存在的执行单元，再讨论要写什么提示词。
- 用户指出的问题：如果没有先明确 Skill 当前要完成的提示词生产任务，就无法判断要调查哪个执行单元，也无法确定信息收集范围；并且实际任务既可能是整套系统提示词，也可能只是其中一部分。
- 修正后的判断：Skill 首先明确本次提示词生产任务、目标产物和范围；然后识别与该范围有关的执行单元，并收集足以完成任务的上下文。
- 范围原则：
  - 写整套系统提示词时，需要理解系统整体架构和各执行单元关系。
  - 写局部提示词时，不要求无差别读取整个系统，只获取目标执行单元的本地运行事实及必要的上下游契约。
  - “渐进式披露”不仅约束最终提示词，也约束 Skill 自身的信息收集：只加载当前阶段、当前产物真正需要的信息。
- 后续校正：仅有“本地运行事实 + 上下游接口 + 继承约束”仍不充分。对照原始输入，还必须加入业务语义与角色边界、关键任务约束及其注意力安排、知识来源与可信度、验收依据。
- 当前结论：最小充分上下文不能只按系统调用范围定义，还要按原始输入的全部检查维度通过就绪判断。

### 判断 3：局部提示词任务的最小充分输入

对照原始输入，局部提示词在开始编写前至少要覆盖以下五类：

1. **目标与交付契约**：为什么写、写哪一部分、目标行为、交付物和完成标准。
2. **运行时事实**：触发时机、可见消息与状态、可用工具、输出结构、异常与拒绝路径。
3. **系统关系与继承边界**：必要上下游接口、实际叠加的底座规则、信息归属，以及明确不应加载的无关内容。
4. **业务语义与关键约束**：业务背景、角色身份、语气、行为边界、领域概念定义、任务重点，以及需要在关键位置重复提醒的高风险约束。
5. **证据与验收依据**：上述事实分别来自哪里，是否存在冲突、过期、推断或可疑知识；提示词完成后用什么案例、规则或 rubric 验证。

这五类是“检查维度”，不是要求无差别读取五份完整资料。Skill 应围绕当前交付范围逐项取证；与目标无关的信息不加载。
