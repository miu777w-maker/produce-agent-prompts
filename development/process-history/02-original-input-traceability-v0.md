## 输入充分性校验结论

曾提出用“目标执行单元的本地信息 + 必要上下游接口 + 实际继承的基础约束”定义局部任务的最小充分上下文。经重新逐条对照原始输入，该定义不充分：

- 它覆盖了运行环境、上下文组成、职责分配和渐进式披露；
- 它遗漏了业务背景中的角色、语气和行为约束；
- 它遗漏了关键任务约束及 Anchor 类注意力安排；
- 它遗漏了可疑知识错误的来源核验；
- 它没有说明最终如何判断生成结果合格。

因此，后续采用五类输入检查：目标与交付契约、运行时事实、系统关系与继承边界、业务语义与关键约束、证据与验收依据。

## 补充边界的追溯

| 用户明确补充 | 对 Skill 设计的约束 |
|---|---|
| Skill 需要思考生成提示词需要哪些内容，以及如何获取 | Skill 不能假设完整输入已经存在，必须包含取证、追问、缺口管理和充分性判断 |
| Skill 既可能生成整套系统提示词，也可能只生成其中一部分 | 先明确本次交付目标与范围，再按范围收集最小充分上下文；局部任务不无差别加载整个系统资料 |
| 资金安全顾问只是背景参考 | 通用流程与案例资料分离；案例用于验证，不写死到核心工作流 |
| 目标是共同完成，而非直接给最终结果 | 每个关键判断先说明从原始输入得出的依据，再由用户参与确认 |
| 分支结束后回归主线 | 持续记录当前主线步骤、分支任务与回归点 |
