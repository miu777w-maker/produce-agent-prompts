# 项目知识库缺口补全与外部取证协议 V0

> 适用环境：提示词生产 Skill 在项目知识库中运行；发现知识疏漏后，由前台人员协调项目人员、后端 Agent、前端 Agent或其他来源完成补充。

## 一、环境角色

- **提示词生产 Skill**：明确生产目标、主动检索知识库、发现知识缺口、生成补全请求、核验返回材料、确认知识已回写、决定是否可以开始生成提示词。
- **前台人员**：接收缺口说明，选择合适的补全途径，转交请求并推动结果进入知识库。
- **项目人员**：补充业务目标、项目决策、角色边界、政策或验收口径。
- **后端仓库 Agent**：检查编排、代码、配置、schema、prompts、evals、测试或日志，并返回可追溯证据。
- **前端仓库 Agent**：检查前端流程、状态、接口调用、用户输入与展示约束，并返回可追溯证据。

任何人员或 Agent 的回答都不是天然正确。提示词生产 Skill仍需检查它是否回答了问题、是否提供直接证据、是否混入推断，以及证据版本是否适用于当前任务。

## 二、什么时候发起知识补全

知识库主动检索后，如果关键事实仍缺失或冲突，则暂停提示词生成并发起补全。Skill 应根据缺口类型建议去向：

- 业务目标、角色、规则或验收决策 → 项目人员；
- Agent 编排、工具、消息、配置或后端运行事实 → 后端 Agent；
- 用户输入、前端状态、交互流程、接口调用或展示约束 → 前端 Agent；
- 跨端契约冲突 → 前后端分别取证，再交项目人员确认目标规则。

典型关键事实包括：

- 实际执行顺序、触发条件或并发关系；
- 系统与任务提示词的真实装配方式；
- 某次执行实际收到的消息、状态和上下文；
- 工具名称、参数、返回值与错误路径；
- 上下游如何消费模型输出；
- 当前 prompts、evals、测试或配置的实际版本；
- 知识库描述与当前实现是否一致。

纯业务目标、角色定位或政策规则缺失时，不应让代码实现替代业务决定。

## 三、知识补全请求的必备内容

每次只围绕一个会阻塞提示词生产的主题，生成可直接复制的请求：

1. **当前提示词生产任务**：正在生成哪部分提示词，目标是什么。
2. **待确认事实**：具体缺少或冲突的内容。
3. **为什么阻塞**：该事实会影响提示词的哪一部分或哪项验收。
4. **建议补充方与检查范围**：说明更适合项目人员、后端 Agent、前端 Agent或其他来源，并列出建议查看的资料。
5. **期望证据**：文件路径、符号名、配置项、schema 字段、测试名或短证据片段。
6. **回答约束**：区分确认事实、推断和未知；不同来源冲突时分别列出；不得用常识补全。
7. **版本信息**：分支、提交、环境或最后更新时间（能够取得时）。

## 四、建议返回格式

```markdown
## 结论

## 已确认事实
- 事实：
  - 证据位置：
  - 适用版本/环境：

## 与知识库描述的差异

## 推断（如有）

## 未能确认的内容

## 建议继续查询的位置
```

## 五、答案返回后的处理

1. 核对回答是否对应原问题，而不是相邻问题。
2. 检查是否给出可定位证据和适用版本。
3. 把事实、推断、未知和冲突分别写入证据台账。
4. 对照知识库中的目标规则：区分“当前实现”和“应该实现”。
5. 将确认信息、来源、版本、适用范围和未决冲突补充进项目知识库。
6. 重新从知识库检索该信息，确认其已成为可追溯的项目知识。
7. 若关键问题仍未解决，生成下一条更窄的补全请求；不生成提示词。
8. 关键输入全部就绪后，返回提示词生产主线。

## 六、通用知识补全请求模板

```markdown
我正在为【目标 Agent / 节点】生产【提示词范围】。当前知识库无法确认【待确认事实】，这会影响【提示词结构、工具调用、上下文引用、行为边界或验收项】。

建议由【项目人员 / 后端 Agent / 前端 Agent / 其他来源】核查或补充：

1. 【精确问题】
2. 【必要的关联问题，非必要则删除】

请优先检查【已知知识条目、文档、目录、文件、符号、配置或 schema；未知可写“请定位最直接来源”】。

返回时请：

- 区分已确认事实、推断和无法确认；
- 为每项事实提供文件路径、符号/配置/schema 名称或测试位置；
- 说明适用的分支、提交、环境或更新时间（能够取得时）；
- 如果代码、配置、prompt、测试之间不一致，分别列出，不要自行合并；
- 不要根据常识补全仓库中不存在的信息。
- 返回内容需要能够带来源补充进项目知识库。
```

## 七、主线回归规则

知识补全是提示词生产过程中的临时分支。每次发起时记录原主线位置；信息回写知识库后，回到“输入就绪检查”，而不是直接跳到提示词编写。
