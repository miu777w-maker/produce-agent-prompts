# 外部评测交接与结果回流模型 V0

> 环境事实：知识库中的提示词生产 Skill 只负责生成 prompts 与 evals；真正的模型、工具和测试执行由后端 Agent 或专门评测环境完成。

## 一、职责边界

### 知识库中的提示词生产 Skill

负责：

- 需求、知识和架构门禁；
- prompt 静态校验；
- eval/rubric/judge prompt 与测试要求生成；
- prompts 与 evals 的同源和追溯检查；
- 生成外部评测交接包；
- 接收评测结果后定位应回退的生产阶段。

不负责：

- 声称模型行为已经实际验证；
- 伪造工具调用记录、黄金集成绩或长对话结果；
- 在没有外部执行证据时给出“全部通过”的行为结论。

### 后端 Agent / 专门评测环境

负责：

- 使用实际模型、工具 schema、运行时上下文和测试集执行评测；
- 保存逐案例输出、工具调用、异常和评分；
- 返回可定位的版本、环境、指标和失败案例。

## 二、Skill 可以给出的状态

- **设计未就绪**：需求、知识或架构仍有阻塞。
- **静态校验未通过**：prompt/eval 的结构、来源、契约或对应关系有问题。
- **待外部评测**：prompts 与 evals 已生成并通过静态校验，尚未执行行为测试。
- **外部评测失败**：收到结果，存在一票否决或未达阈值项。
- **外部评测通过**：仅在收到可追溯执行结果并满足阈值后使用。
- **最终交付就绪**：需求、静态检查、外部评测及必要修订均完成。

## 三、外部评测交接包

至少包含：

- 本次任务与目标提示词清单；
- prompts 路径和版本；
- evals、rubric、judge prompt 和黄金集要求；
- 实际加载顺序与上下文组装说明；
- 所需模型、工具和 schema；
- 必须覆盖的正常、边界、模糊、异常、对抗或长对话路径；
- 一票否决项与通过阈值；
- 期望返回格式；
- 知识卡来源映射；
- 尚未确定但不阻塞执行的说明。

## 四、建议的评测结果返回格式

```markdown

## 执行环境
- prompts 版本：
- evals 版本：
- 模型与参数：
- 工具/schema 版本：
- 代码分支/提交或评测环境：
- 执行时间：

## 总结
- 执行案例数：
- 通过/失败：
- 一票否决：
- 关键指标：

## 失败案例
- Case ID：
  - 输入与上下文：
  - 期望：
  - 实际输出/工具调用：
  - 失败的 eval 条目：

## 未能执行的项目

## 原始结果位置
```

## 五、结果回流后的诊断

Skill 不应收到失败结果后直接改 prompt。先判断失败来源：

- 需求或验收理解错误 → 回需求解析；
- 知识缺失或知识内容错误 → 回知识发现/补全；
- 提示词职责或上下文架构错误 → 回架构设计；
- 逐字指令表达问题 → 回当前提示词单元；
- eval 错误、黄金答案错误或 judge 不可靠 → 修正评测材料；
- 后端运行环境或工具配置问题 → 返回后端执行方处理；
- 模型能力或稳定性限制 → 记录限制，再由项目决定策略。

## 六、是否回写知识库

当前用户尚未确定统一策略，因此 Skill 应先读取项目契约或任务说明；没有约定时输出建议，不自行把所有评测日志制成知识卡。

### 建议进入知识库的内容

- 经评测确认的系统行为或能力边界；
- 反复出现且已定位原因的提示词缺陷；
- 已知限制和适用条件；
- 项目采用的指标、阈值和一票否决决定；
- 某个正式版本的评测结论与原始结果链接；
- 促使业务规则、架构或提示词职责发生变化的结论。

### 通常留在评测产物区的内容

- 大量逐轮原始日志；
- 临时调试输出；
- 可由报告重新计算的中间数据；
- 没有形成稳定结论的一次性失败。

### prompts 与 evals 的沉淀

它们是否直接作为知识库卡片内容，取决于项目契约：

- 当前资金安全顾问项目采用“知识卡是来源，`prompts/` 与 `evals/` 是同项目派生产物”的分离方式；
- 其他类似知识库若把逐字 prompt/eval 也作为卡片权威内容，Skill 应遵循该项目契约，并处理卡片制品与可执行文件的同步。

通用 Skill 不写死唯一存储方式，但必须保证知识源、可执行文件和评测结果之间能够追溯。

## 七、任务暂停与恢复

交接外部评测后，主线状态记为“待外部评测”，保存 prompts/evals 版本和返回要求。结果回来后恢复原任务，先做结果诊断，再进入修订分支；不能把等待期间的新版本结果混入旧版本。
