# 暂存任务：提示词缺失知识补全产物审验

> 日期：2026-08-11  
> 类型：初版审验期间发现的暂存项  
> 状态：当前 Skill 已有机制，待用真实任务验证是否充分  
> 主线回归点：用户使用 Claude 对现有 prompts 进行初版审验。

## 一、需要确保的能力

Skill 发现无法继续生产或检验 prompt 的关键知识缺口时，不能只给出“信息不足”的结论。必须形成可直接用于补充知识的产物。

## 二、当前 Skill 已有设计

当前 `knowledge-discovery-and-gaps.md` 和 `artifact-templates.md` 已要求知识补全请求包含：

- 当前任务与受影响阶段；
- 已知事实及来源；
- 缺失或冲突的具体问题；
- 为什么阻塞以及影响哪些 prompts/evals；
- 需要返回的业务事实、决策、schema、代码或运行时证据；
- 建议回答方：项目人员、后端 Agent、前端 Agent 或其他来源；
- 回写知识库所需的来源、版本和适用范围；
- 补全后重新执行的门禁和主线回归点。

补充内容必须进入知识库并被重新检索，不能直接用临时聊天答案绕过门禁。

## 三、边界

- Skill 可以从知识库中继续发现并整理已经存在但尚未找到的内容；
- Skill 可以根据已有证据形成待确认草案，但必须标注推导和待确认状态；
- Skill 不能凭空生成未知的业务决策、运行事实或工具契约，并把它们当作真实知识；
- 需要外部回答时，产物应足够具体，让回答方知道查什么、返回什么，而不是宽泛提问。

## 四、初版审验要观察

1. 是否准确指出缺失知识，而非泛称背景不足；
2. 是否区分可继续从知识库检索与必须外部补充；
3. 是否选择合适的项目人员、后端 Agent 或前端 Agent；
4. 请求是否包含可执行的问题、所需证据和返回格式；
5. 是否只阻塞受影响范围；
6. 补全后是否回到知识发现重新验证，而不是直接写 prompt；
7. 是否避免把推测内容当成正式补充结果。

## 五、后续动作

先通过 Claude 的实际审验观察现有机制。若输出仍停留在“缺什么”的提示，而不能成为可复制的补全任务，再增强模板、示例或阶段门禁。
